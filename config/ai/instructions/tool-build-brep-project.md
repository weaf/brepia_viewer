Scalar fields may be a finite numeric literal, a direct published-parameter reference such as `{ "parameter": "width" }`, or a bounded expression AST. Binary expressions use exactly two arguments: `{ "op": "add" | "sub" | "mul" | "div", "args": [left, right] }`. Unary negation uses exactly one argument: `{ "op": "neg", "args": [value] }`. Respect scalar units. `add` and `sub` require compatible equal dimensions. `mul` is only for dimensionless scaling (`none * X` or `X * none`). `div` may divide by a dimensionless scalar (`X / none -> X`) or divide equal dimensions (`X / X -> none`). Native primitive coordinate semantics are centered-origin semantics. A `box` is centered on its local origin, so width W and depth D occupy X = -W/2..W/2 and Y = -D/2..D/2. A `cylinder` is likewise centered on its local origin. `transform.translate` is a displacement from that centered local origin; it is not an absolute coordinate measured from a box minimum corner. Therefore a concentric/centered cylindrical through-hole in a centered box normally uses the same local origin (for example translate `[0, 0, 0]`), not `[W/2, D/2, 0]`. Use the bounded scalar AST for arithmetic such as half-widths or clearance offsets instead of freezing those relationships into numeric literals.

`transform.rotateDeg = [rx, ry, rz]` uses the canonical M6 rotation convention. Angles are degree-compatible bounded M1 scalars and may be literals, published-parameter references or bounded scalar expressions. The tuple is interpreted as build123d/OCCT-style **Intrinsic XYZ** rotation about the canonical local origin. Positive angles follow the ordinary right-hand rule. Conceptually, the local geometry is first rotated by the Intrinsic-XYZ orientation and then translated by `transform.translate`, so a local point follows `p' = R_intrinsicXYZ * p + T`. Do not reinterpret the tuple as arbitrary extrinsic XYZ, yaw/pitch/roll strings, axis-angle, quaternion or matrix data. A transform still requires a single-shape input and returns one `single`; it does not accept an `instanceSet`. When translation is omitted use zero translation; when rotation is omitted use zero rotation. Keep derived angle relationships in the existing bounded degree-scalar AST rather than baking them into literals.

`extrude` is the bounded M4 profile-to-solid feature. Its `profile` is inline canonical data, not a separate graph node or reusable non-solid result. Supported profile variants are `{ "type": "rectangle", "width": ..., "height": ... }`, `{ "type": "circle", "radius": ... }`, and `{ "type": "closedPolyline", "points": [{ "u": ..., "v": ... }, ...] }`. Rectangle width/height, circle radius, every closed-polyline U/V coordinate and extrusion `depth` may be millimetre-compatible literals, published-parameter references or bounded scalar expressions. Rectangle dimensions, circle radius and extrusion depth must resolve strictly positive. A closed polyline must contain 3 through 32 ordered vertices; closure from the final vertex back to the first is implicit, so do not repeat the first vertex at the end. At effective parameter values it must remain a simple non-degenerate loop: no zero-length edges, zero area or self-intersection. The profile is centered on the local origin for rectangle/circle; closed-polyline coordinates are explicit in the local profile plane. `axis: "x"` means U=Y, V=Z and normal +X; `axis: "y"` means U=Z, V=X and normal +Y; `axis: "z"` means U=X, V=Y and normal +Z. Extrusion is symmetric from `-depth/2` through `+depth/2` along that normal and always returns one `single` solid. It can therefore be consumed wherever another single-shape node is allowed. Do not invent arbitrary workplanes, arbitrary extrusion vectors, open profiles, holes/multiple loops, profile/sketch graph nodes, constraints, splines/NURBS or topology references; those are outside the current M4 surface.

`revolve` is the bounded full-revolution profile-to-solid feature. Full 360 degrees is implicit: there is no angle, start-angle or partial-sweep field. It reuses the inline `BrepProfile` grammar, but the first supported revolve surface is a `closedPolyline`; do not use centered `rectangle` or `circle` profiles because those cross the rotation axis under the canonical frame and are rejected. For every revolve axis, profile `u` is the axial coordinate and profile `v` is non-negative radial distance from the rotation axis. `axis: "x"` maps `(u,v)` to `(u,v,0)`, so U=+X and V=+Y; `axis: "y"` maps `(u,v)` to `(0,u,v)`, so U=+Y and V=+Z; `axis: "z"` maps `(u,v)` to `(v,0,u)`, so U=+Z and V=+X. The selected canonical axis passes through the local origin. Every resolved profile point must keep `v >= 0`; a negative radial value is unsupported axis crossing. If the profile touches `v = 0`, it must do so through a real non-zero-length boundary segment on the axis rather than isolated point contact. The profile must also remain a simple non-degenerate closed loop with no zero-length edge, zero area or self-intersection. Revolve returns exactly one `single` solid; do not invent arbitrary axes, topology-attached axes, reusable sketch/profile nodes, open profiles, spline/NURBS profiles, multiple loops, partial angles or new scalar functions.

`sweep` is the bounded first path-based solid feature. Use it only for one constant circular profile following exactly one planar 90-degree elbow path. The only supported profile is `{ "type": "circle", "radius": ... }`. The only supported path is `{ "type": "planarElbow90", "planeNormalAxis": "x" | "y" | "z", "firstLegLength": ..., "secondLegLength": ..., "bendRadius": ... }`. The two leg lengths are the straight portions only; `bendRadius` is the centerline radius. The path starts at the local origin, travels +U for the first leg, turns through one tangent +90 degree circular arc, then travels +V for the second leg. `planeNormalAxis: "x"` means U=+Y,V=+Z,N=+X; `"y"` means U=+Z,V=+X,N=+Y; `"z"` means U=+X,V=+Y,N=+Z. The circular section radius, both leg lengths and bend radius are millimetre-compatible bounded scalars and must resolve strictly positive; the section radius must remain strictly smaller than the bend radius. Sweep returns exactly one `single` solid. Do not approximate a requested smooth elbow with boxes/cylinders, and do not invent arbitrary path points, arbitrary bend angles, multiple bends, non-planar rails, rectangle/polyline sweep profiles, profile holes, variable sections, twist, Frenet/roadlike options, guide rails or reusable path/sketch graph nodes. If the requested path is outside this bounded shape, explain the limitation instead of fabricating geometry.

`linearPattern` is the bounded one-dimensional multi-instance composition node. It references exactly one existing single-shape `input`, uses `axis: "x" | "y" | "z"`, a literal integer `count` from 2 through 32, and a non-zero millimetre-compatible `spacing` scalar. `spacing` may be a literal, published-parameter reference or bounded M1 scalar expression. Instance index 0 is the unshifted input; later instances are translated by `index * spacing` along the selected axis, preserving canonical index order. A linear pattern returns an `instanceSet`, not one fused solid. It may be the primary `resultNodeId`, in which case Brepia and Grasshopper expose all instances as separate ordered bodies/Breps. It may also be used as a `subtract.tools[]` entry; subtraction then applies every pattern instance as an ordered cutter. Do not replace a requested repeated multi-body result with a Boolean union merely to satisfy single-body semantics.

`rectangularPattern` is the bounded two-dimensional multi-instance composition node and reuses the same `instanceSet` result model as `linearPattern`. It references exactly one existing single-shape `input`. `axisA` and `axisB` must each be `"x" | "y" | "z"` and must be different. `countA` and `countB` are literal integers from 2 through 32 and their product must not exceed 64. `spacingA` and `spacingB` are independent non-zero millimetre-compatible scalars and may each be literals, published-parameter references or bounded M1 scalar expressions. Instance `(a,b)` is translated by `a * spacingA` along `axisA` plus `b * spacingB` along `axisB`. Ordering is row-major with `a` as the outer loop and `b` as the inner loop, so the stable flat index is `a * countB + b`; Brepia body identity is `<patternId>::<index>`. A rectangular pattern may be the primary `resultNodeId`, exposing the ordered instances separately, or one `subtract.tools[]` entry, applying every ordered instance as a cutter. It may not consume a `linearPattern`, another `rectangularPattern`, or any other `instanceSet`, and no single-only consumer may consume its result.
